# jfrader-ui

React component system built from scratch, with Emotion styles and CSS custom properties for themes.

Documentation and live component demos are hosted at **[ui.jfrader.com](https://ui.jfrader.com)**, with the Storybook workbench available at **[ui.jfrader.com/storybook/](https://ui.jfrader.com/storybook/)**.

The documentation site is generated by [`@jfrader/storybook-docs`](https://www.npmjs.com/package/@jfrader/storybook-docs) directly from the library's CSF3 story files (`*.stories.tsx`) in `@jfrader/ui`. Component introductions, usage notes, props tables, and code snippets stay colocated with story code so documentation is never written twice.

## Guides

- [Getting started](docs/consuming-jfrader-ui.md): install, render your first component, and set up React / Vite or Next.js.
- [Theming](docs/theming.md): light/dark, saved preferences, brand colors and scoped themes.
- [Styling](docs/styling.md): props, `sx`, `styled`, `css` and component parts.
- [QA gates and accessibility](docs/qa-gates.md): keyboard, screen reader, forced colors, reduced motion and RTL verification.

The same guides are available under **Foundations** in [Storybook](https://ui.jfrader.com/storybook/). Component pages in the documentation site and Storybook contain interactive examples, props tables, keyboard behavior, and usage notes.

## Install

```sh
npm i @jfrader/ui @jfrader/tokens
```

Requires React 19. Import `@jfrader/tokens/tokens.css` once in your app entry. See [Getting started](docs/consuming-jfrader-ui.md) for a complete working file; installing the package alone does not load its token stylesheet.

### Registry choice

npmjs is the default and needs no configuration. GitHub Packages hosts the same
verified tarball and requires authentication even for public npm packages:

```ini
@jfrader:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}
```

The registry setting applies to the whole `@jfrader` scope. npm does not fall
back from GitHub Packages to npmjs. If your project uses GitHub for that scope,
authenticate there. For a package not mirrored there, use an explicit npmjs
tarball URL.

## Commands

Run from the repo root.

| Command | What it does |
| --- | --- |
| `pnpm generate` | Generate `tokens.css` and `vars.ts` from the token source |
| `pnpm dev` | Generate tokens and start Storybook on port 6006 |
| `pnpm build` | Generate tokens, build static Storybook and static docs front (when `DOCS_BUILD=1`) |
| `pnpm test` | Generate tokens and run Storybook tests in the browser |
| `pnpm typecheck` | Typecheck every package |
| `pnpm verify:docs` | Check component documentation coverage |
| `pnpm --filter @jfrader/docs dev` | Start docs front dev server on port 5173 |
| `pnpm --filter @jfrader/docs build` | Sync README to guidance and build docs front |

### Documentation overview sync

The overview page in `apps/docs` reads from `apps/docs/guidance/index.md`, which is synced from this `README.md` by `apps/docs/scripts/sync-readme.mjs`.

Running `pnpm --filter @jfrader/docs dev` or `pnpm --filter @jfrader/docs build` executes this sync automatically before Vite starts. The generated `apps/docs/guidance/index.md` is git-ignored so `README.md` remains the single source of truth.

## Packing packages

Root `pnpm build` builds Storybook. Build the published packages separately:

```sh
pnpm --filter @jfrader/tokens build && pnpm --filter @jfrader/ui build
pnpm --filter @jfrader/tokens exec npm pack --dry-run --json
pnpm --filter @jfrader/ui exec npm pack --dry-run --json
```

Each package's `prepack` builds and validates only its own exports, and its `postpack` restores only its own source exports. Tokens can be packed without UI's `dist/`:

```sh
pnpm --filter @jfrader/tokens pack --pack-destination /tmp/opencode
```

UI depends on the published tokens package and does not bundle it. Build tokens before packing UI; UI's hook does not build or validate tokens:

```sh
pnpm --filter @jfrader/tokens build
pnpm --filter @jfrader/ui pack --pack-destination /tmp/opencode
```

The default `node scripts/flip-exports.mjs dist` validates both packages and requires both builds. If packing fails after `prepack`, restore workspace exports with `node scripts/flip-exports.mjs src`.

## Publishing

`@jfrader/tokens` and `@jfrader/ui` release together from `.github/workflows/publish.yml`.

1. Set the same `version` in `packages/tokens/package.json` and `packages/ui/package.json` and merge to `master`.
2. Push an annotated tag on that commit: `git tag -a vX.Y.Z -m vX.Y.Z && git push origin vX.Y.Z`.
3. The workflow checks both package names and versions against the tag and checks that the commit is on `master`. It runs typecheck, tests and `verify:exports`, builds both packages, and packs each one once with `pnpm pack` (`workspace:*` becomes the released version). It verifies or publishes those exact tarballs to npmjs and GitHub Packages, tokens before UI.

An existing matching artifact is accepted. A different artifact at the same version fails the release. To re-run a release without re-tagging:

```sh
gh workflow run publish.yml --repo jfrader/jfrader-ui --ref v0.1.1
```

Each npmjs package uses a trusted publisher for `jfrader/jfrader-ui` → `.github/workflows/publish.yml`; no npm token is stored. Publish the first version of each package by hand, then configure its trusted publisher in npmjs settings. npmjs requires the package to exist before adding a trusted publisher. GitHub Packages uses the workflow's scoped `GITHUB_TOKEN`.

GitHub creates a personal package as private on its first publication. After the first workflow succeeds, make each package public once from its **Package settings → Danger Zone → Change visibility**. Later versions keep that setting.

## Browser support

Components rely on `:has()`, `:dir()`, `inert` and modal `<dialog>`, and Vite 8 builds to its `baseline-widely-available` target (Chrome 111, Firefox 114, Safari 16.4). Storybook 10 sets a higher floor for the workbench only.

- Components (`@jfrader/ui`): Chrome and Edge 120+, Firefox 121+, Safari 16.4+, iOS Safari 16.4+, Chrome for Android 120+.
- Storybook workbench: Chrome 131+, Edge 134+, Firefox 136+, Safari 18.3+. Mobile browsers: not verified.
- `Textarea` `autoResize` needs `field-sizing: content`; without it the field keeps its `rows` height. Dialog close requests fall back to a state close where `dialog.requestClose()` is missing.
- Automated: `pnpm typecheck` and `pnpm test` (story play tests and the axe gate, headless Chromium only). CI runs them on pushes to `master` and on pull requests; the publish workflow runs them again on `v*` tags.
- Manual: keyboard, screen reader, forced colors, reduced motion and RTL in [docs/qa-gates.md](docs/qa-gates.md).
